# web

The site at [whereismytaxmoney.com](https://whereismytaxmoney.com): a reader enters
what they paid in income tax and sees where it went.

Astro with React islands, static output, deployed to GitHub Pages. Mobile first.
The design was authored at 430px and most of the audience is on a phone.

```bash
npm install
npm run dev        # transform the dataset, then serve
npm test           # allocation maths against fixtures generated by the Python
npm run build      # transform, typecheck, build to dist/
npm run fixtures   # regenerate tests/fixtures.json from the Python (needs python3)
```

## Where the numbers come from

`scripts/build-data.mjs` reads `../data/dist/dataset.v3.json`, which is committed,
so this build needs no Python and no `uv`. It writes one view model per financial
year to `public/data/`, plus a small `src/data/summary.json` that is inlined into
the prerendered HTML so the landing page renders complete with no fetch. Both
outputs are gitignored: they are derived, and `dev` and `build` regenerate them.

The transform is written to fail loudly. Every list it emits is checked against a
total the dataset publishes separately: each lens must account for the exact
published union total, both lenses must agree with each other, and devolution and
the cess must close against theirs. A silent mismatch would be a wrong figure on a
site whose entire claim is that the figures are right.

## The design

Ported from a Claude Design project on the **Organic** design system.
`src/styles/organic.css` is vendored from there and should be treated as
generated: retune it upstream and re-sync rather than editing here. The one
intentional edit is documented at the top of the file.

**The comp shipped its own invented dataset and none of it is used.** It had ten
purpose heads, twelve ministries, five years and hand-written sub-line
percentages; the real dataset has eleven groups, fifty-six ministries, six years
and published amounts at every node. The comp is the visual and interaction spec.
Two places where this implementation departs from it on purpose:

- **Cess is not inside union spending.** The comp folded it into the union bucket,
  so it appeared both there and as its own part of the three-way split. Cess is
  earmarked financing credited to reserve funds, and the dataset makes it an
  invariant that the `financing` perimeter is never summed with `union-spending`.
  It gets its own line and its own drill-down instead.
- **No `1/1.1` pool factor.** The comp discounted the states' share twice. The
  divisible pool is gross tax minus cess and surcharge, and those are already
  removed before the award percentage is applied.

## The allocation maths

`src/lib/allocate.ts` is a port of `scripts/allocate.py`, itself the display-side
twin of `../data/wimtm_data/apportion.py`. Three implementations of one algorithm
is not a mistake that can be tidied away: the split depends on the figure a reader
types, so it cannot be precomputed into the dataset.

Because three copies agreeing by inspection is not evidence, `npm run fixtures`
generates cases from the Python and `npm test` requires this port to reproduce
them exactly: 9 apportionment cases, 25 tax splits, and 18 end-to-end journeys
that run the whole thing in both languages and compare rupee for rupee. CI fails
if the committed fixtures are stale.

Two things that port badly and are worth knowing about:

- **`apportion` runs in BigInt.** It computes `total * weight` before dividing,
  and on national figures that product reaches ~1e27, past
  `Number.MAX_SAFE_INTEGER` by eleven orders of magnitude. For the amounts a
  reader types it would not matter; allocating the whole union budget across 56
  ministries drifts by ₹10 without it.
- **Rounding is half-to-even, not `Math.round`.** Python's `round()` breaks ties
  toward the even neighbour and JavaScript's does not. ₹57 at a 10% surcharge
  gives a base of ₹50, and 41% of that is exactly 20.5: Python says 20,
  `Math.round` says 21. The fixtures caught this. Nothing about the code looked
  wrong.

Everything is allocated in **whole rupees**, at display precision, so what you see
is what is conserved. A row showing ₹0 means less than a rupee of your tax, which
is honest rather than hidden, and with 56 ministries on screen it is common.

## Still to do

- **The share card does not carry the reader's own figure.** There are cards
  now: `scripts/build-og.mjs` draws nineteen at build time, one per category and
  one per year. But GitHub Pages serves identical HTML for every query string,
  so one page can only ever name one image. A per-share card needs a Cloudflare
  Worker in front.

  The spike this file used to ask for has been done, and the answer is **do not
  render images at the edge**: the free plan allows 10 ms of CPU and a 3 MB
  script, and satori plus resvg-wasm is well over the first and roughly double
  the second. The cheap version is better anyway. The breakdown is
  *proportional* to the amount, so the card's shape is identical whatever the
  reader paid: only the rupee figures scale. Put the amount in the **title**
  instead, where WhatsApp, X and LinkedIn render it as large text, and let
  `HTMLRewriter` rewrite `og:title`, `og:description` and `og:image` when
  `?paid=` is present. That is a few hundred microseconds of CPU, no wasm, no
  font buffers, and it points `og:image` at a card that already exists.

  Bucketing the amount into the image is strictly worse: it means showing either
  a vague range or a number that is not the reader's, on a site whose whole
  claim is that the figures are right.

- **`src/lib/site.ts` has one placeholder left.** `REPO_URL` carries an owner
  and name inferred from the git author and the directory, so check it against
  the actual remote: a wrong value ships a 404 in the footer rather than the
  blank it replaced.

  The contact address is resolved. "Report a problem" now opens a Google Form
  with the reader's topic, message and page already filled in, rather than a
  `mailto:` to an address that was one character off the maintainer's real one.
  A form also works on a phone with no mail client configured. The prefilled
  page URL has `paid` and `sur` stripped from it first: the amount somebody
  typed in is the one number here that is nobody else's business, and it is not
  handed to a third party just because it sat in a query string.

- **Nothing is deployed yet.** There is no git remote and the domain has no DNS
  record. GitHub Pages needs Settings, Pages, Source: **GitHub Actions** (not
  "deploy from a branch", because the workflow uses `deploy-pages@v4`), the
  custom domain field filled in, and apex `A`/`AAAA` records pointing at
  GitHub's four addresses. On Cloudflare, create them **DNS-only** first:
  GitHub's certificate validation fails behind an orange cloud.
